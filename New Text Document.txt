1. Input Layer (Client-Side)
Web Upload Interface: A frontend component allowing users to upload existing images (JPG/PDF) from their device storage. This requires client-side validation for file type and size to prevent unnecessary server load.

Browser Camera Capture: Utilizes the MediaDevices.getUserMedia() API to stream raw video frames or capture static images directly from the user’s camera.

2. API Gateway
Function: Acts as the single entry point for all client requests.

Responsibilities: Handles rate limiting, authentication (JWT validation), and request routing to the appropriate backend service. It serves as a buffer to protect the core Transaction Controller from malicious or malformed traffic.

3. NestJS Backend (Core Logic)
Transaction Controller: * Acts as the orchestrator. It receives the multipart form data (image + metadata) and generates a unique transactionId for tracking.

Duplicate Detection: Before processing, it queries the MongoDB database using unique constraints (e.g., hash of store name, receipt number, and date) to identify potential duplicates.

Message Queue (BullMQ/Redis): * Crucial for scalability. Since OCR and AI structuring are computationally expensive and time-consuming, the API offloads the task to a background worker. This prevents the HTTP request from timing out and allows for asynchronous processing.

Image Preprocessing Pipeline (Sub-process):

Grayscale Conversion: Reduces complexity by removing color data.

Adaptive Thresholding: Binarizes the image to separate text from background noise.

Deskewing: Corrects the orientation of the receipt if it was scanned at an angle.

Normalization/Resizing: Ensures standard resolution for higher OCR accuracy.

4. AI & Processing Layer
OCR Engine (Tesseract): Extracts raw text data from the preprocessed images.

LLM Structuring: Takes the raw text output from Tesseract and performs entity extraction (mapping text to fields like vendor_name, total, line_items). This layer is essential for converting unstructured OCR text into a machine-readable JSON format.

5. Frontend (Ionic)
User Feedback & Correction: Provides a real-time UI for the user to verify the structured data.

Conflict Resolution UI: Displays the "Duplicate Warning Prompt." If the user chooses "Rewrite/Overwrite," the frontend sends an explicit confirmation flag back to the backend to update the existing record.

6. Data Persistence (MongoDB)
Collection Schema: Stores the final, validated JSON object. It is modeled to support flexible line-item arrays and status tracking (pending, completed, failed), allowing the frontend to poll for status updates seamlessly.
